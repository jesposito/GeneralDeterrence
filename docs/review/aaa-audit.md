# General Deterrence — AAA Readiness Audit

_Multi-agent code + design audit · 11 review dimensions + coverage critic · 126 adversarially-verified findings · 2026-07-07_

## Executive Summary

General Deterrence is a genuinely promising 90-second arcade trainer that already runs, plays, and ships with a leaderboard, PWA, mobile controls, and researched NZ-law content — but it sits at prototype quality, not production/AAA. The single most urgent issue is silent data loss: the primary Fly deployment declares no persistent volume, so every deploy wipes the entire leaderboard and the officer emails it collects — fix this first. Its reason to exist is compromised too: the flagship SituationalJudgement legal mini-game is unreachable dead code, and the one version that would run prints its own answer key. Feel and feedback are half-wired — the on-screen message channel flickers invisibly, the biggest failure (a lost life) has no shake/text/sound, most scoring actions are silent, and there's no music — all inside a single 1,200-line god component with zero automated tests. The path is clear: about a week of cheap high-leverage fixes (data-loss, broken WASD/CapsLock controls, dead teaching content, feedback wiring) plus a focused month on audio/juice, mobile performance, balance, and accessibility would credibly reach a shipped-indie-AAA bar.

**Overall grade:** C+ — a fun, polished-feeling prototype that runs and ships, but well short of shipped-indie-AAA: 1 critical data-loss bug, a broken flagship teaching loop, god-component architecture, half-wired feedback, and broad a11y/perf/security gaps. Roughly 6–9 weeks of focused single-dev work to close the gap (~1 week of quick wins, ~1 month of high-impact feel/perf/balance/a11y, plus the structural big rocks).

> **Dedup note:** Merged ~20 cross-lens duplicates into single findings, keeping the highest severity where merges spanned ratings: (1) the Dispatched-Call dead subsystem surfaced 4x (architecture/game-loop/react-ts/gameplay); (2) the 60Hz setStationaryCountdown re-render storm 3x; (3) siren-has-no-drain/dead-state 3x; (4) the four separate dead-tuning-constant findings folded into one (including the LAR 2.0-vs-1.5 multiplier drift and the uncapped reverse speed); (5) gameMessage key={Date.now()} flicker 3x; (6) HUD-meters-hidden-on-touch 2x; (7) engine-drone-dies-permanently, combining the blur/orientation path and the mute/start-muted path; (8) useKeyPress re-subscription 2x; (9) held-key e.repeat, combining E/C/M strobing and the RIDS auto-confirm; (10) 'core scoring actions silent' (audio lens + gameplay warn-payoff lens); (11) life-lost/big-moment juice (game-feel shake/hit-stop + missing HUD text/message); (12) matchMedia-per-frame 2x; (13) pinch-zoom/user-scalable=no 2x; (14) leaderboard client-authoritative/no-validation (backend + coverage gap); (15) runtime-CDN-dependency (mobile-pwa + coverage gap); (16) no-CI/typecheck gate (backend + coverage gap); (17) no-error-boundary + unguarded loop Map throws (react-ts + coverage gap); (18) gameLoop phantom-deps folded into the god-component finding. ## Prioritized Roadmap

### ⚡ Quick Wins — high value, low effort

- [ ] Key the gameMessage banner on message content, not Date.now() — restores the entire on-screen coaching channel that is currently an invisible flicker.
- [ ] Add a Fly [[mounts]] volume for /data so deploys stop silently wiping the leaderboard and stored emails — the one critical bug.
- [ ] Normalize e.key casing at the input boundary — fixes CapsLock-dead WASD and the Shift-release 'self-driving' stuck key.
- [ ] Add `if(e.repeat)return` to the E/C/M and RIDS-confirm handlers — stops siren/minimap strobing and the held-SPACE auto-confirm of warn/enforce.
- [ ] Gate setStationaryCountdown to whole-second changes (or read it at hudTick) — removes the 60Hz full-Game re-render storm while parked.
- [ ] Restart the engine drone on visibility/focus/unmute and drop the muted early-return — stops it dying permanently after the first rotate/tab-switch/mute.
- [ ] Wrap SituationalJudgement's principle in `{result && …}` — stop printing the answer key before the player chooses.
- [ ] Harden the leaderboard POST: clamp score to a plausible max, cap name/email length, add express.json({limit}) and express-rate-limit.
- [ ] Give the life-lost event weight — camera shake + red '-LIFE LOST' floating text + gameMessage (plus a lightweight hit-stop on big wins/saves).
- [ ] Wire the silent audio moments: 3-2-1-GO countdown, the -3s incorrect-RIDS penalty, desktop UI clicks, and unlock audio on the launch gesture.
- [ ] Fix the two latching HUD animations — advance prevVigilance unconditionally and drop scoreDisplay from the count-up effect deps.
- [ ] Remove user-scalable=no (scope touch-action:none to the canvas), honor prefers-reduced-motion for canvas shake, and add focus-visible rings to modal buttons.
- [ ] Add a PR CI gate (tsc --noEmit + build), drop the container to USER node, and switch the server image to npm ci with a committed lockfile.
- [ ] Reserve HUD space so the mute toggle stops covering the SHIFT-ENDS-IN countdown, and require finalScore>0 before celebrating 'New High Score!'.

### 🎯 High-Impact — biggest AAA gains

- [ ] Restore the flagship teaching loop: route Restraints/Distractions through SituationalJudgement so the NZ-law mini-game actually runs (lifts live mini-game variety 2→3).
- [ ] Wire the full audio feedback map — scoring wins, warns, blob pickups, failures, wall collisions, boost — using the existing but under-used synths.
- [ ] Add a procedural music/ambient bed that rises with shift tension, and rebuild the siren wail as a self-sustaining oscillator so it stops dying after 5.6s.
- [ ] Land the three big rendering wins for mobile fps: frustum-cull off-screen entities, cut per-entity shadowBlur, and make camera/swerve/particles frame-rate-independent.
- [ ] Make mobile first-class: a compact touch HUD (boost/vigilance/deterrence readouts), a touch-correct tutorial, and fix the joystick touch-down lurch + direction-gated BOOST.
- [ ] Rebalance the economy toward the deterrence thesis: nerf the 5000-pt LAR save, cost the siren, pay presence in real time, widen Enforce-vs-Warn, and add a late-shift climax.
- [ ] Establish real leaderboard integrity (signed per-run token or server-derived score) and fix PII handling (consent line + erasure path, or drop email for a resume token).
- [ ] Bundle Tailwind/React/fonts first-party via the Vite build and add a service worker so the installable PWA genuinely works offline.
- [ ] Bring the game to an accessible bar: dialog semantics + focus trap on modals, canvas label + event live-region, a reduced-motion-safe Speed mini-game, labelled forms, and shape/label (not color-only) indicators.

### 🪨 Big Rocks — large structural efforts

- [ ] Break up the 1,200-line Game.tsx god component: extract a React-free simulation module (pure step fns over a typed World+dt) plus useGameLoop and useInput hooks — the prerequisite for testability, tuning, and parallel work.
- [ ] Replace refs-as-truth with a lightweight store (Zustand or useSyncExternalStore + selectors), deleting the 10Hz hudTick hack and the 19-prop HUD firehose.
- [ ] Strengthen the type model: Vec2 alias, named ScoreState, discriminated-union Civilian with guards, counter-based entity IDs, and reconciled App/shift phase unions.
- [ ] Decide-and-purge the zombie subsystems and dead tuning surface: implement or delete the Dispatch system, the dead constants, and the ~706-LOC React-DOM render path.
- [ ] Stand up an automated test + CI safety net covering scoring math, geometry helpers, and the server validation contract.
- [ ] Add a controls layer: a single action→binding map with a rebinding UI (localStorage-persisted) and Gamepad support.

#### ⚪ Dockerfile build-dependency cleanup ships in a prior layer — saves no image size, comment is misleading
`Dockerfile:20, 28-29` · **low** · effort **S** · _build-config_

- **Issue:** `apk add --no-cache python3 make g++` (line 20), `npm install --omit=dev` (line 26), and `apk del python3 make g++` (line 29) are three separate RUN layers. Docker layers are additive, so the toolchain added in layer 20 still ships in the final image; the later apk del only writes whiteouts on top. The comment 'Cleanup build dependencies to reduce image size' (line 28) is therefore false — the delete reduces nothing.
- **Fix:** Collapse into one RUN using a virtual package: `RUN apk add --no-cache --virtual .build-deps python3 make g++ && npm ci --omit=dev && apk del .build-deps` so the toolchain never lands in a persisted layer. (Better long-term: build better-sqlite3 in the builder stage and copy node_modules over so the runtime needs no compiler.)
- **Impact:** Unnecessarily large image (slower pulls/deploys, a full C toolchain in the runtime attack surface) plus a comment that misleads maintainers into thinking size is optimized.
- **Verify:** Verified: lines 20, 26, 29 are three distinct RUN instructions; a later apk del cannot shrink an earlier committed layer. Fix is the standard --virtual pattern and is sound. (Note: musl/alpine has no better-sqlite3 prebuild, so the toolchain is genuinely needed at build time — the issue is purely that it's not confined to one layer.)

#### ⚪ Wildcard CORS on the score-submission API
`server/index.js:35` · **low** · effort **S** · _cors_

- **Issue:** `app.use(cors())` with no options (index.js:35) sends Access-Control-Allow-Origin: *, so any website can drive POST /api/leaderboard from a visitor's browser. The same server hosts the SPA same-origin (express.static at index.js:39 + catch-all at 122; App.tsx:9 defaults API_BASE to the relative /api), so cross-origin access isn't needed for the game to work.
- **Fix:** Scope CORS to the known origin(s): `cors({ origin: process.env.ALLOWED_ORIGIN \|\| false })`, or drop the cors middleware entirely since the frontend is served same-origin.
- **Impact:** Low on its own, but it widens the abuse surface for the anti-cheat/rate-limit gaps by letting arbitrary origins drive submissions from their visitors.
- **Verify:** Verified: index.js:35 `app.use(cors())` (wildcard); SPA is served same-origin (index.js:39/122; App.tsx:9). Fix is sound.

#### ⚪ vite `define` bakes GEMINI_API_KEY into the public client bundle
`vite.config.ts:16-19` · **low** · effort **S** · _secrets-handling_

- **Issue:** The define block (vite.config.ts:16-19) inlines env.GEMINI_API_KEY into both process.env.API_KEY and process.env.GEMINI_API_KEY at build time. define does literal text substitution into the client bundle, so any value set for GEMINI_API_KEY ships in plaintext to every browser. - **Impact:** No current leak, but a latent secret-exposure trap in the build config; removing it eliminates the risk and the dead configuration.
- **Verify:** Verified: define block present at vite.config.ts:16-19; grep across *.ts/*.tsx (excluding node_modules/dist) shows no reads of process.env.API_KEY or GEMINI_API_KEY in game code — no live leak, latent footgun as described.

#### ⚪ No CI quality gate — only a Docker image build on tags
`.github/workflows/docker-publish.yml:3-8` · **low** · effort **M** · _ci_

- **Issue:** The single workflow (docker-publish.yml) only builds/pushes the image on tag/release events. #### ⚪ Email dedup query can't use idx_email — full table scan on every email submit
`server/index.js:31, 50` · **low** · effort **S** · _efficiency_

- **Issue:** index.js:31 creates `CREATE INDEX idx_email ON leaderboard(email)` (raw column), but the dedup lookup at index.js:50 is `SELECT id, score FROM leaderboard WHERE LOWER(email) = LOWER(?)`. SQLite can only use an index for `LOWER(email) = ?` if there is an expression index on `LOWER(email)`; the plain-column index does not satisfy it, so every email submit does a full table scan. Functionally the case-insensitive dedup still works — it just never uses the index, and this degrades as the (currently unbounded) table grows.
- **Fix:** Either index the expression — `CREATE INDEX idx_email_lower ON leaderboard(LOWER(email))` — or normalize email to lowercase on insert and drop LOWER() from the query so the existing idx_email is used.
- **Impact:** Negligible on a tiny board, but combined with the unbounded row growth it means write-path latency creeps up over time with no cap; a one-line index fix removes it.
- **Verify:** New finding (reviewer missed). Verified: idx_email is on raw `email` (index.js:31); getByEmail filters on LOWER(email) (index.js:50). Standard SQLite behavior — expression predicate can't use a plain-column index.

#### ⚪ fly.toml defines no Fly-native health check — the Dockerfile HEALTHCHECK is ignored on Fly
`fly.toml:10-16` · **low** · effort **S** · _deploy-config_

- **Issue:** fly.toml declares [http_service] but no [[http_service.checks]] / [checks] block (verified: no 'check'/'health' keys anywhere in fly.toml). Fly Machines do NOT honor a Dockerfile HEALTHCHECK instruction — health checks must be defined in fly.toml — so the carefully-written /api/health probe (Dockerfile:49) is dead weight on the primary hosted target. Fly's proxy will still do a basic TCP connect, but there is no HTTP health gating: a deploy that starts but is broken (e.g. DB open fails yet the process stays up) won't be caught, and rolling deploys aren't health-gated.
- **Fix:** Add a Fly HTTP check to fly.toml, e.g. under [http_service]: `[[http_service.checks]]\n  interval = "15s"\n  timeout = "3s"\n  method = "get"\n  path = "/api/health"` so Fly actually probes the endpoint and gates deploys on it.
- **Impact:** The one health endpoint the app exposes is never exercised on Fly, so a running-but-broken deploy can serve errors indefinitely without Fly noticing or restarting it.
- **Verify:** New finding (reviewer's healthcheck finding was compose-only). Verified: fly.toml has no [checks]/[[http_service.checks]] section; Dockerfile:49 HEALTHCHECK exists but Fly ignores Dockerfile HEALTHCHECK (documented Fly Machines behavior — checks live in fly.toml).

## Appendix B — Coverage Gaps / Not Yet Reviewed

Aspects the coverage critic flagged as deserving AAA scrutiny beyond the 11 review dimensions.

#### 🔴 Leaderboard anti-cheat / score integrity (server trust boundary)
**Severity:** critical · **Where:** `server/index.js:35,76-100 (POST handler, cors); App.tsx:59-73; components/GameOver.tsx:253-259,340; server/package.json:9-13 (no helmet/rate-limit dep)`

The leaderboard IS the game's competitive/social hook, and it is trivially forgeable. The POST handler accepts a fully client-computed score with the only check being `typeof score !== 'number'` (server/index.js:80), no auth, no HMAC/session token, no magnitude cap, and CORS is wide open (`app.use(cors())`, server/index.js:35). The client sends `finalScoreBreakdown.finalScore` verbatim (App.tsx:63,72), and the client-supplied `timestamp` is stored as-is (server/index.js:84). Anyone can `curl -X POST /api/leaderboard` with a max score from any origin and permanently own the board, and NaN/Infinity pass the number check. `name`/`email` have no server length limit (client `maxLength={20}` at GameOver.tsx:340 is cosmetic), so a multi-MB field is a storage/DoS vector. Fix (effort M): clamp score to a plausible 90s-shift maximum server-side, enforce name/email length caps, add per-IP rate limiting (express-rate-limit is a 5-line add), restrict CORS to the app origin, and ignore the client timestamp in favor of Date.now().

#### 🟠 Email PII collected and stored with no consent, security, or erasure (NZ Privacy Act exposure)
**Severity:** high · **Where:** `components/GameOver.tsx:344-351; App.tsx:59-73; server/index.js:22-31,49-59,87-97`

This is a New-Zealand-Police-branded tool whose users are likely officers entering work emails.
